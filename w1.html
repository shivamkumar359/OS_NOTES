Operating Systems — Fingertip Concise Notes (Week 1)

1. What is an Operating System?

Operating System (OS): Software that acts as an intermediary between the user and computer hardware.

Two Views of OS

View Meaning
User-centric Provides an easy interface and services to users
System-centric Allocates resources and controls system operations
Exam Point: OS = Resource Allocator + Control Program + Interface

2. Computer System Structure

A computer system has 4 main components:

  1. Hardware: CPU, memory, I/O devices
  2. Operating System: Controls and coordinates hardware
  3. Application Programs: Word processors, browsers, compilers, DBMS, games
  4. Users: People, machines, other computers
Fingertip: Hardware → OS → Applications → Users

3. What Does an OS Do?

Depends on the type of system.

  • Provides convenience
  • Improves performance
  • Manages system resources
  • Supports multiple users/programs
  • Optimizes battery life in handheld systems
  • Embedded systems may have little/no user interface

4. Computer Startup

At power-up/reboot:

Bootstrap Program → Initializes System → Loads OS Kernel → Starts Execution

Bootstrap Program

  • Stored in ROM/EPROM
  • Also called firmware
  • Loads the OS kernel into memory
Exam: Bootstrap program is the first program executed during startup.

5. Computer-System Operation

  • CPU and I/O devices can work concurrently.
  • Each device has a device controller.
  • Controller has a local buffer.
  • Data moves between main memory ↔ local buffer.
  • After completing an operation, the controller sends an interrupt to the CPU.
Fingertip: Device → Controller → Buffer → Memory → Interrupt

6. Storage Hierarchy

Storage systems are organized as a hierarchy based mainly on:

  • Speed
  • Cost
  • Volatility

Faster storage is generally more expensive and smaller.

7. Caching

Caching: Copying information from slower storage to faster storage temporarily.

How it works

  1. Check faster storage (cache).
  2. If data is present → use it directly.
  3. If absent → copy data from slower storage to cache.
  4. Use the cached copy.

Cache is smaller than the storage it represents.

Important cache issues

  • Cache size
  • Replacement policy
  • Cache management
Fingertip: Cache = Small + Fast + Temporary copy

8. Device Driver

Device Driver: Software that manages a particular device controller.

It:

  • Manages I/O devices
  • Provides a uniform interface between the device controller and OS kernel

9. Multiprogramming

Multiprogramming: Keeping multiple jobs in memory so the CPU always has something to execute.

Why?

A single program may wait for I/O, leaving the CPU idle.

Working

Job A running → A waits for I/O → OS switches to Job B

Goal: Improve CPU utilization and efficiency.

10. Timesharing / Multitasking

Timesharing: Extension of multiprogramming where the CPU switches between jobs very frequently.

This allows users to interact with programs while they are running.

  • Provides interactive computing
  • Response time should generally be < 1 second
  • Each user has at least one program in memory → Process

If multiple jobs are ready → CPU Scheduling is required.

Difference

Multiprogramming Timesharing
Focuses on CPU utilization Focuses on interactive response
Switches when job waits Switches frequently
Mainly efficiency Mainly user interaction

11. Operating-System Operations

OS operation is interrupt-driven.

Types of Interrupts

  1. Hardware Interrupt: Generated by hardware/device.
  2. Software Interrupt: Also called exception/trap.
    • Examples: Division by zero, Request for OS service, Other process-related problems

12. Dual-Mode Operation

Used to protect the OS and other system components.

Two modes:

  1. User Mode
  2. Kernel Mode

Mode Bit: Hardware mechanism that identifies the current mode.

Privileged Instructions

Certain instructions can only execute in kernel mode.

Mode Transition

User Program → System Call → Kernel Mode → Return → User Mode

Exam: Privileged instructions cannot be executed directly in user mode.

13. Major Tasks of OS

The OS mainly manages:

  1. Process Management
  2. Memory Management
  3. I/O Management
  4. File Management
  5. Storage Management
  6. Protection & Security

14. Process Management

Process: A program in execution.

Program Process
Passive entity Active entity
Stored code Code currently executing
No execution state Has execution state/resources

A process may require: CPU, Memory, I/O, Files, Initialization data.

When a process terminates, OS must reclaim its resources.

OS Process Activities

  • Create/delete processes
  • Suspend/resume processes
  • Process synchronization
  • Process communication
  • Deadlock handling

15. Memory Management

To execute a program:

  • Instructions must be in memory.
  • Required data must be in memory.

Memory Management: Determines what is in memory and when.

Main Activities

  • Track used/free memory
  • Decide what enters/leaves memory
  • Allocate memory
  • Deallocate memory
  • Improve CPU utilization and response time

16. Storage & File-System Management

OS provides a logical view of storage: Physical storage → File

File-System Activities

  • Create/delete files
  • Create/delete directories
  • Manipulate files/directories
  • Map files to secondary storage
  • Backup files
  • Access control

Files are usually organized into directories.

17. I/O Management

OS hides hardware-specific details from users.

I/O subsystem handles:

  • Buffering: Temporary storage while data is transferred.
  • Caching: Stores frequently/actively used data in faster storage.
  • Spooling: Overlaps output of one job with input of another.

Also provides:

  • General device-driver interface
  • Device-specific drivers
Fingertip:
Buffer = Temporary transfer storage
Cache = Faster copy for performance
Spool = Overlap I/O operations

18. Protection & Security

  • Protection: Controls access of processes/users to system resources.
  • Security: Protects the system from internal and external attacks. (Examples: Viruses, Worms, Denial-of-service, Identity theft, Theft of service)

User Identification

  • User ID: Identifies a user
  • Group ID: Identifies a group of users
  • IDs are associated with files/processes to control access.
  • Privilege escalation: Changing to an ID with greater permissions.
Exam:
Protection = Access control
Security = Defense against attacks

19. User Interfaces

CLI — Command Line Interface

Allows users to directly enter commands.

  • Shell: Fetches commands, Executes commands, Can have different implementations (e.g., Unix/Linux shells)

GUI — Graphical User Interface

Uses: Mouse, Keyboard, Monitor, Icons, Windows/folders.

Many operating systems support both CLI and GUI.

Touchscreen Interface

Uses: Gestures, Virtual keyboard, Touch-based selection, Voice commands.

20. System Calls

System Call: Programming interface through which programs request services from the OS.

Programs usually access system calls through APIs (e.g., Windows API, POSIX API, Java API).

Fingertip: Application → API → System Call → OS

21. Types of System Calls

Type Examples
Process Control Create, terminate, execute, wait
File Management Create, delete, open, close, read, write
Device Management Request/release, read/write device
Information Maintenance Get/set time, system/process/file information
Communication Send/receive messages, shared memory
Protection Access control, permissions

Communication Details

Two major approaches:

  1. Message Passing: Processes send/receive messages.
  2. Shared Memory: Processes share memory regions.

22. UNIX Structure

Traditional UNIX structure is:

  • More than a simple structure
  • Not completely layered
  • Contains a UNIX kernel

23. OS Impact on AI/Data Science

Modern AI/DS workloads depend heavily on OS functionality.

Process & Thread Management

Training uses multiple processes/threads. OS scheduler affects: Training time, Latency, CPU-GPU overlap, GPU utilization.

Memory Management

AI models require large amounts of memory. OS manages Virtual memory, Page faults, Shared memory.

  • Problems: Excessive swapping → slower training; Memory fragmentation → allocation failures.

File System & I/O

Training data may be read repeatedly across epochs (ImageNet, CSV/Parquet, TFRecords, WebDataset).

Therefore: Caching + Buffering → Important for training performance.

  • mmap(): Maps a file into virtual memory.
  • Prefetching: Loads the next batch while the current batch is being processed.

24. GPU & Accelerator Interaction

OS manages:

  • GPU drivers
  • DMA transfers
  • Context switching

OS/kernel scheduling affects GPU utilization. NUMA-aware memory placement can improve performance.

25. Networking for Distributed AI

Distributed training uses: Sockets, RDMA, TCP/IP, RoCE.

OS networking affects: All-reduce latency, Parameter synchronization speed.

Note: RDMA/kernel bypass → Lower latency than traditional sockets.

26. Containers & MLOps

Tools such as Docker and Kubernetes depend on OS features.

  • Namespaces: Isolation
  • cgroups: Resource control
  • Virtual file systems

OS can enforce: CPU limits, GPU limits, Memory limits, Job isolation.

EXAM ONE-LINERS

  • OS = Interface between user and hardware.
  • OS as resource allocator = Manages and allocates system resources.
  • OS as control program = Controls program execution and I/O devices.
  • Process = Program in execution.
  • Multiprogramming = Multiple jobs kept in memory to keep CPU busy.
  • Timesharing = Frequent CPU switching for interactive computing.
  • Interrupt = Signal indicating an event requiring CPU attention.
  • Kernel mode = Mode where privileged instructions can execute.
  • User mode = Restricted mode for user programs.
  • System call = Interface for requesting OS services.
  • Device driver = Software that manages a device/controller.
  • Caching = Copying data from slower to faster storage.
  • Protection = Controlling access to resources.
  • Security = Defending the system against attacks.
  • CLI = Command-based user interface.
  • GUI = Graphical user interface.

Fingertip Memory Lines

  • OS = Interface + Resource Manager + Control Program
  • Computer System = Hardware + OS + Applications + Users
  • Startup = Bootstrap → Kernel → OS Execution
  • I/O = Device → Controller → Buffer → Memory → Interrupt
  • Multiprogramming = Keep CPU Busy
  • Timesharing = Fast Switching → Interactive Computing
  • Process = Program + Execution
  • System Call = Program → API → OS
  • Protection = Who can access what?
  • Security = How do we defend the system?
  • Buffer = Temporary transfer storage
  • Cache = Fast copy
  • Spooling = Overlapping I/O
  • AI + OS = CPU + Memory + I/O + GPU + Network + Containers

15-Second Revision

OS provides an interface between users and hardware and manages system resources. The major OS responsibilities are process, memory, I/O, file, storage, protection and security management. Multiprogramming keeps the CPU busy, while timesharing provides interactive computing. Interrupts handle hardware/software events, and dual-mode operation protects the OS. Programs request OS services through system calls. Modern AI workloads depend heavily on OS scheduling, memory, I/O, GPU, networking, and container-management features.
