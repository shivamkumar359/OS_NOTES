Operating Systems — Memory Management

1. Introduction to Memory Management

What is Memory Management?

Memory management is the operating system function responsible for managing main memory (RAM) and deciding:

  • Which processes should be kept in memory.
  • Where processes should be placed.
  • How memory addresses are translated.
  • How memory is protected.
  • How processes can use more memory than the available physical RAM.

Why do we need it?

CPU scheduling requires multiple processes to be kept in memory at the same time. Therefore, after learning CPU Scheduling, we study ways to efficiently manage memory.

Memory-management techniques range from:

Primitive / Bare Machine → Simple allocation → Partitioning → Segmentation → Paging → Virtual Memory

Key Point: The choice of a memory-management method depends on several factors, especially the hardware architecture/design.

2. Background

How does the CPU use memory?

The CPU executes instructions using the Program Counter (PC). The basic sequence is:

Program Counter → Fetch instruction → Decode instruction → Fetch operands (if required) → Execute instruction → Store result (if required)

Example

Suppose an instruction says: ADD A, B

The CPU may need to:

  1. Fetch the instruction.
  2. Fetch the values of A and B.
  3. Perform the addition.
  4. Store the result.

Therefore, a running program generates a sequence of memory addresses.

Exam Point: The OS is mainly concerned with the sequence of memory addresses generated by a running program because memory management must correctly map and protect those accesses.

3. Basic Hardware

Main Memory and Registers

A program must first be brought from disk/storage into main memory before it can execute. The CPU can directly access:

CPU Registers → Cache → Main Memory (RAM) → Disk / Storage

Important Points

  • Registers are directly accessible by the CPU.
  • Main memory is also directly accessible by the CPU.
  • Memory receives: an address + read request, or an address + data + write request.
  • Register access usually takes one CPU clock cycle or less.
  • Main-memory access can take many CPU cycles. Slow memory access can cause the CPU to stall.
  • Cache is placed between the CPU and main memory to reduce access time.
  • Memory protection is necessary so that one process cannot improperly access another process's memory.
Fingertip:
Registers → Fastest
Cache → Fast
RAM → Slower
Disk → Slowest

4. Logical Address vs Physical Address

This is one of the most important concepts in memory management.

Logical Address

A logical address is the address generated by the CPU. It is also called a Virtual Address.

Physical Address

A physical address is the actual address seen by the memory hardware.

CPU generates → Logical / Virtual Address → Address Translation → Physical Address → Main Memory

Address Space

  • Logical Address Space: The set of all logical addresses generated by a program.
  • Physical Address Space: The set of physical memory addresses corresponding to the program's memory references.

Address Binding

Address binding determines when logical addresses are converted/bound to physical addresses.

  1. Compile-Time Binding: If the physical memory location is known at compile time. (Logical Address = Physical Address)
  2. Load-Time Binding: Address binding takes place when the program is loaded into memory. (Logical address = Physical address in the sense that the program's generated address is directly tied to its physical location after binding)
  3. Execution-Time Binding: Binding takes place while the program is executing. (Logical / Virtual Address ≠ Physical Address)
Exam Point: Execution-time binding requires hardware support for address translation.

5. Base and Limit Registers

A pair of registers can be used to protect a process's memory.

  • Base Register: Stores the starting physical address of the process.
  • Limit Register: Stores the size/range of the valid address space.
Physical Memory
Base →  +-------------------------+
         |     Process Memory      |
Limit →  +-------------------------+

For every memory access generated in user mode, the CPU checks whether the address is within the permitted range:

  • If address is within allowed range → ACCESS
  • If address is outside allowed range → PROTECTION ERROR
Purpose: Base and limit registers provide memory protection.
Fingertip:
Base = Where process starts
Limit = How far process is allowed to go

6. Memory-Management Unit (MMU)

Definition

The Memory-Management Unit (MMU) is a hardware component that performs address translation at run time.

Virtual / Logical Address → MMU → Physical Address → Main Memory

Relocation Register

In a simple execution-time address translation scheme, the value in the relocation register is added to every address generated by the user process. The base register is also called the relocation register in this context.

Example:
Logical Address = 250
Relocation Register = 1000
Physical Address = 1000 + 250 = 1250

Important Points

  • The user program works only with logical addresses.
  • The user program does not see actual physical addresses.
  • Address binding occurs when a memory reference is made. This is execution-time binding.
Fingertip: Physical Address = Relocation/Base Register + Logical Address

7. Segmentation & 8. User's View of a Program

Definition

Segmentation is a memory-management scheme that supports the programmer's/user's logical view of a program. A program is viewed as a collection of logical units called segments.

Examples of Segments / User's View

Instead of seeing the program as one continuous block, the user sees it as several logical components:

  • Main program
  • Procedures / Functions / Methods
  • Global variables / Local variables
  • Stack / Arrays / Objects / Symbol table

This matches the natural logical structure of a program.

9. Logical View of Segmentation & 10. Architecture

Segments do not necessarily have to be stored contiguously in physical memory.

Logical Program        Physical Memory
+---------+            +------------------+
| Segment1|            | Segment 1        |
+---------+            +------------------+
| Segment2|            | Other Process    |
+---------+            +------------------+
| Segment3|            | Segment 3        |
+---------+            +------------------+
| Segment4|            | Free Space       |
+---------+            +------------------+
                       | Segment 4        |
                       +------------------+
                       | Segment 2        |
                       +------------------+

Segmentation Architecture

A logical address in segmentation can be represented as:

| Segment Number | Offset |

  • The segment number identifies the segment.
  • The offset identifies the location inside that segment.
  • The segment table contains information about each segment, including its physical location and size.

11. Segmentation Protection & 12. Important Problem

Segmentation Protection

Each segment-table entry can contain a:

  • Validation Bit: validation bit = 0 → Illegal segment.
  • Protection Privileges: R = Read, W = Write, X = Execute.
    Example: Code Segment → Read + Execute | Data Segment → Read + Write

Sharing: Protection and sharing can be applied at the segment level (e.g., code sharing).

Important Problem with Segmentation

Segments are variable-sized. Therefore, memory allocation becomes a Dynamic Storage-Allocation Problem. Finding suitable free areas can become difficult.

Fingertip: Segmentation
= Variable-sized logical units
= Matches user's program view
= Dynamic allocation required

13. Paging & 14. Frames and Pages

Definition

Paging is a memory-management technique in which physical memory is divided into fixed-size blocks and logical memory is divided into equally sized blocks. The important advantage is that a process does not need to occupy contiguous physical memory.

Frames and Pages

  • Physical Memory is divided into fixed-sized blocks called Frames.
  • Logical Memory is divided into blocks of the same size called Pages.
Important Rule: Page size = Frame size

15. Properties of Paging & 16. Page Table

Page/Frame Size

The size is a power of 2 (ranges from 512 bytes to 16 Mbytes).

Allocation

To run a program containing N pages, you need N free frames. The frames do not have to be physically adjacent. The process is still valid even though the pages are scattered.

Page Table

A page table maps logical pages to physical frames.

Page 0 → Frame 5 | Page 1 → Frame 2 | Page 2 → Frame 9 | Page 3 → Frame 1

The page table is therefore used for: Logical-to-Physical Address Translation.

17. Why Paging is Useful

Advantages

  • A process can occupy non-contiguous physical memory.
  • It avoids external fragmentation.
  • It avoids the problem of allocating variable-sized physical chunks.

Disadvantage

Paging still causes Internal Fragmentation because the final page may not be completely filled.

Comparison

Feature Segmentation Paging
Unit Segment Page
Size Variable Fixed
Matches logical program structure Yes No
Physical allocation Variable-size Fixed-size frames
External fragmentation Possible Avoided
Internal fragmentation Usually not the main issue Possible

18. Address Translation in Paging & 19. Address Space

A CPU-generated logical address is divided into:

| Page Number (p) | Page Offset (d) |

  • Page Number (p): Used as an index into the page table to get the physical frame/base address.
  • Page Offset (d): Gives the exact location inside the page/frame.
Important Point: The offset does not change during translation. Only the page number is translated into a frame number.

Address Space and Page Size

For a logical address space of 2^m and a page size of 2^n:

  • Number of pages = 2^(m-n)
  • Number of offset bits = n
Exam Formula:
Offset bits = log2(Page Size)
Page number bits = Logical Address bits - Offset bits

20. Paging Example & 21. Free Frames

Paging Example

Given logical address space m = 4 (16 bytes total) and Page size = 4 bytes (n = 2).

  • Since Page size = 4 = 2^2, offset requires 2 bits.
  • Logical address has 4 bits total.
  • Page number bits = 4 - 2 = 2.

| Page Number (2 bits) | Offset (2 bits) |

The address translation mechanism uses the page number to locate the corresponding frame and combines that frame with the offset.

Free Frames

The OS keeps track of all currently available frames. The exact mapping depends on which free frames were selected from the free-frame list upon allocation.

22. Paging Hardware with TLB

A page-table lookup can itself require a memory access. To make address translation faster, systems use a TLB — Translation Lookaside Buffer.

The TLB is a fast associative memory containing recently used page-table entries.

CPU → Logical Address
         |
         v
       [ TLB ] ——— (TLB miss) → Page Table → Frame Number
         | (TLB hit)
         v
    Frame Number
         |
         v
  Physical Address → Main Memory
  • TLB Hit: Page number is in the TLB. Translation is faster.
  • TLB Miss: Page number is not found. A memory access to the Page Table is required, and the TLB is updated for future accesses.
Fingertip: TLB = Fast cache for page-table entries

23. Virtual Memory (Background) & 24. Definition

Background

A program does not necessarily use every part of its code or data at the same time (e.g., error-handling code, unusual routines). Loading the entire program into memory is often unnecessary. This leads to the idea of Virtual Memory.

Definition of Virtual Memory

Virtual memory separates the user's logical memory from the actual physical memory. Only the required portion of a program needs to be in physical memory at a particular time. Therefore:

Logical Address Space > Physical Address Space

A process may have a logical address space much larger than the available physical RAM.

25. Advantages of Virtual Memory

  1. Larger programs can run: The entire program does not need to be in physical memory.
  2. More processes can run concurrently: Each process requires less physical memory at a time.
  3. Better CPU utilization: More processes can remain available for execution.
  4. Better throughput: More work can be completed over time.
  5. Less unnecessary I/O: Only required portions of a program need to be loaded.
  6. Efficient process creation.
  7. Memory sharing: Virtual address spaces can support sharing between processes.
  8. Program size is no longer strictly limited by physical RAM.
Important Note: Virtual memory can increase CPU utilization and throughput without an increase in response time or turnaround time, assuming suitable system conditions.

26. Virtual Address Space & 28. Larger Than Physical Memory

The virtual address space represents the logical view of how a process is stored. It is normally viewed as a contiguous sequence of logical addresses (Page 0, Page 1, Page 2...).

Meanwhile, physical memory is divided into page frames (Frame 0, Frame 1...). The MMU maps the virtual pages to physical frames.

Virtual Memory Larger Than Physical Memory

This is possible because only the currently required portions (pages) need to be resident in RAM.

Virtual Memory (Large Address Space)
         |
         | (Only required parts)
         v
Physical Memory (Required pages)

27. Virtual Memory Implementation & 29. Demand Paging

Virtual memory can be implemented using:

  • Demand Paging
  • Demand Segmentation

Definition of Demand Paging

In demand paging, a page is loaded into physical memory only when it is needed.

  • Traditional loading: Load entire process into memory.
  • Demand paging: Load only required pages initially → Load additional pages when needed.

30. Advantages of Demand Paging & 31. Lazy Swapper

Advantages of Demand Paging

Less I/O, Less memory usage, Faster initial response, More users/processes can be supported, No need to load unnecessary pages.

Example: A program contains 100 pages but initially uses only 10. Demand paging loads only those 10.

Lazy Swapper / Pager

A lazy swapper never brings a page into memory unless that page is actually needed. A swapper that deals specifically with pages is called a Pager.

Fingertip:
Lazy = Do not load until needed
Pager = Swapper that works with pages

32. What Happens When a Page is Needed? & 33. Valid-Invalid Bit

When the CPU references a page:

Page Reference → Is page valid? → No (Not in memory) → Page Fault → Load page

If the reference is completely invalid (out of bounds), it results in an abort.

Valid-Invalid Bit

Each page-table entry contains a valid-invalid bit.

  • Valid (v): page is in memory
  • Invalid (i): page is not in memory

Initially, all page-table entries are set to i because pages have not yet been loaded.

34. Page Table When Some Pages Are Not in Main Memory

Example of a Page Table with missing pages:

Page Table
+------+-------+---------------+
| Page | Bit   | Frame Number  |
+------+-------+---------------+
|  0   |   v   |       5       |
|  1   |   i   |      --       |
|  2   |   v   |       2       |
|  3   |   i   |      --       |
|  4   |  ...  |      ...      |
+------+-------+---------------+

If the CPU requests Page 1 or Page 3, a Page Fault will occur, triggering the OS to load the missing page into a free frame and update the table.
