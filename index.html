Week 1: OS Concepts & Architecture

Topics 1 – 26

1. What is an Operating System?

Operating System (OS): Software that acts as an intermediary between the user and computer hardware.

ViewMeaning
User-centricProvides an easy interface and services to users
System-centricAllocates resources and controls system operations
Exam Point OS = Resource Allocator + Control Program + Interface

2. Computer System Structure

A computer system has 4 main components:

  • Hardware: CPU, memory, I/O devices
  • Operating System: Controls and coordinates hardware
  • Application Programs: Word processors, browsers, compilers, DBMS, games
  • Users: People, machines, other computers
Hardware → OS → Applications → Users

3. What Does an OS Do?

  • Provides convenience & improves performance
  • Manages system resources & supports multi-user operations
  • Optimizes battery life in handheld systems
  • Embedded systems may operate with minimal or no user interface

4 & 5. Startup & Computer-System Operation

Bootstrap Program → Initializes System → Loads Kernel → Starts Execution

Bootstrap Program: Stored in ROM/EPROM (firmware); executed first upon boot/restart.

I/O Operation

  • CPU and I/O devices work concurrently.
  • Device controllers maintain a local buffer; transfers occur between main memory ↔ local buffer.
  • Controller raises an interrupt to notify CPU when work completes.
Device → Controller → Buffer → Memory → Interrupt

6 – 8. Storage Hierarchy, Caching & Drivers

  • Storage Hierarchy: Ranked by Speed, Cost, and Volatility (faster storage = smaller & more expensive).
  • Caching: Temporary storage in faster media. Steps: Check cache → Hit (use directly) → Miss (fetch from slow storage to cache). Key trade-offs: Cache size, replacement policy, management.
  • Device Driver: Translation software that provides a uniform OS interface to device controllers.
Cache = Small + Fast + Temporary copy

9 & 10. Multiprogramming vs. Timesharing

FeatureMultiprogrammingTimesharing (Multitasking)
Primary FocusCPU utilization & efficiencyInteractive response (< 1s)
Switch TriggerWhen current job waits for I/OFrequent switching via timer intervals
GoalKeep CPU constantly busyConcurrent multi-user execution

11 & 12. Interrupts & Dual-Mode Protection

OS is interrupt-driven: Hardware Interrupts (bus signals) vs. Software Interrupts/Traps (exceptions, system calls).

Dual-Mode Protection

Differentiated via a hardware Mode Bit (User Mode = 1, Kernel Mode = 0).

User Program → System Call (Trap) → Switch to Kernel Mode → Execute → Return to User Mode
Exam Privileged instructions can only execute in Kernel Mode.

13 – 17. Core OS Subsystems

  • Memory Management: Tracks free/used memory; dynamic allocation/deallocation.
  • Storage & File Systems: Logical abstraction of raw storage; manages directories, mapping, and ACLs.
  • I/O Subsystems:
    • Buffering: Temporary storage during transfers.
    • Caching: Storing active data in faster memory.
    • Spooling: Overlapping output of one job with input of another (e.g., printers).
Buffer = Temp Transfer | Cache = Faster Copy | Spool = Overlap I/O

18 – 22. Protection, Interfaces & System Calls

Protection vs Security: Protection controls internal access (User ID / Group ID). Security protects against external attacks (malware, DoS).

System Call TypeOperations / Examples
Process Controlfork(), exec(), exit, wait, memory allocation
File Managementopen, close, read, write, reposition, delete
Device Managementrequest, release, read, write device attributes
Informationget/set time, system info, process attributes
CommunicationMessage passing (pipes/sockets) vs Shared Memory
Protectionchmod, access permission control
App → API → System Call → OS Kernel

23 – 26. Modern OS in AI, Data Science & MLOps

  • Scheduler: Impacts CPU-GPU overlap, training latency, and batch scheduling.
  • Memory Management: Limits swapping and memory fragmentation. Employs mmap() for large-file virtual memory mapping and batch prefetching.
  • Accelerators: Manages GPU kernel drivers, DMA transfers, and NUMA-aware topologies.
  • Distributed Networking: RDMA / RoCE bypasses kernel TCP stacks for low-latency All-Reduce parameter synchronization.
  • Containers (Docker/K8s): Leverages Linux Namespaces (isolation) and cgroups (enforcing CPU, memory, and GPU limits).

Week 2: Processes, Threads & IPC

Topics 1 – 13

1. Process Concept ★

Process: A program in execution. Loaded into memory from disk.

ComponentPurpose
Text / CodeExecutable machine instructions
Program Counter + RegistersCurrent execution state and activity
StackFunction parameters, return addresses, local variables (grows downward)
HeapDynamically allocated memory via malloc() / new (grows upward)
Data SectionGlobal and static variables
Exam Program = Passive entity on disk; Process = Active entity executing in memory.

2. Process States ★

StateMeaning
NewProcess is currently being created
RunningInstructions are actively being executed on the CPU
Waiting (Blocked)Waiting for an event or I/O completion
ReadyLoaded and waiting to be assigned to a CPU core
TerminatedProcess has finished execution
New → Ready ↔ Running → Waiting → Ready → Terminated

3. Process Control Block (PCB) ★★★

Also known as a Task Control Block (TCB). Serves as the repository for any information that varies from process to process:

  • Process State: Ready, running, waiting, etc.
  • Program Counter: Address of the next instruction to execute.
  • CPU Registers: Accumulators, index registers, stack pointers.
  • CPU Scheduling Info: Process priority, scheduling queue pointers.
  • Memory-Management Info: Page tables, segment tables, base/limit registers.
  • Accounting Info: CPU time used, time limits, account numbers.
  • I/O Status Info: List of allocated I/O devices and open files.
Exam One-Liner PCB stores the complete execution context and metadata of a process.

4. Context Switch ★★★

Switching the CPU core to another process requires saving the state of the old process into its PCB and loading the saved state of the new process from its PCB.

Save State to PCB_old → Load State from PCB_new
  • Context-switch time is pure overhead (system does no useful work during the switch).
  • Speed is heavily bounded by memory speeds, number of registers, and hardware support.
Context Switch = Pure Overhead (Save Old PCB + Load New PCB)

5 & 6. Process Creation & Termination ★★

Processes form a tree structure identified by a unique PID (Process Identifier).

UNIX System Calls

  • fork(): Creates a new child process by duplicating the address space of the parent.
  • exec(): Replaces the process's memory space with a new program.
  • wait(): Blocks parent until child process finishes and collects its exit code.
  • exit(): Terminates the process and returns status to OS.
  • abort(): Allows parent to forcefully terminate a child (e.g., resource limit exceeded).
fork() = Create Duplicate | exec() = Replace Program Space

7 & 8. Zombie, Orphan & Cascading Termination ★★★

ConceptDefinitionKey Characteristic
Zombie Process Child has terminated, but parent has not yet called wait(). Process is dead; exit status and entry remain in process table.
Orphan Process Parent has terminated without calling wait(). Child is alive; adopted by root/init process (PID 1), which calls wait().
Cascading Termination OS policy where parent termination automatically terminates all child descendants. Initiated by OS kernel.
Exam Tip Zombie = Dead child waiting for parent • Orphan = Alive child whose parent died.

9 – 11. Interprocess Communication (IPC) ★★★

Processes can be Independent or Cooperating (cooperation enables speedup, modularity, and resource sharing).

IPC ModelMechanismCharacteristics & Trade-offs
Shared Memory Processes establish a shared region of address space. Very fast; user processes must handle data synchronization explicitly.
Message Passing Messages exchanged via send() and receive() primitives. Useful for distributed systems; kernel-mediated; no shared variables required.
Shared Memory → Fast / Needs Sync | Message Passing → Send / Receive

12. Remote Procedure Call (RPC)

Abstracts procedural calls between networked processes using structured network stubs:

  • Client Stub: Acts as a local proxy; marshals (packs) parameters and targets remote server port.
  • Server Stub: Receives packet, unmarshals (unpacks) parameters, executes routine, returns results.
Client Stub → Marshal | Server Stub → Unpack & Execute

13. Pipes ★★

A communication conduit connecting standard input/output streams between processes.

FeatureOrdinary Pipes (Anonymous)Named Pipes (FIFOs)
DirectionalityUnidirectional (one-way)Bidirectional (half-duplex or full-duplex)
RelationshipRequires parent-child relationshipNo parent-child relationship required
LifetimeExists only while processes are runningPersists in file system until deleted
AccessUsed by two related processesMultiple processes can read and write
Warning In ordinary pipes, if unused write/read ends are not explicitly closed, the reader process may block forever waiting for EOF.

⚡ Complete Summary

An OS provides an interface between users and hardware while managing core system resources (processes, memory, storage, I/O, protection). Multiprogramming keeps CPU busy; timesharing guarantees interactive response. Processes are active programs executing in memory, represented by a PCB. Transitions between processes incur context switch overhead. IPC is established via Shared Memory (fast, requires user sync) or Message Passing (kernel-mediated). Dead children uncollected by parents are Zombies; children with terminated parents are Orphans adopted by init.
